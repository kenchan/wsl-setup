## Architecture

This is a WSL Gentoo setup repository using **mitamae** (mruby-based provisioning tool) for system configuration management. The setup is divided into two main phases:

1. **System configuration** (`system.rb`) - Runs with sudo privileges
2. **User configuration** (`user.rb`) - Runs as regular user

### Key Components

- **mitamae**: Provisioning tool downloaded to `bin/mitamae` (version 1.14.0)
- **Platform detection**: Automatically detects platform (Gentoo/Arch) and includes appropriate recipes
- **Recipe structure**: 
  - `system/[platform]/default.rb` - Platform-specific system packages and configs
  - `user/[component]/default.rb` - User-level component configurations
  - Configuration files stored in `*/files/` subdirectories

## Common Commands

### Initial Setup
```bash
# Download and setup mitamae binary
bin/setup

# Apply system configuration (requires sudo)
sudo bin/mitamae local system.rb

# Apply user configuration (run as regular user)
bin/mitamae local user.rb
```

### Development
```bash
# Test system configuration changes
sudo bin/mitamae local system.rb

# Test user configuration changes  
bin/mitamae local user.rb

# Test specific recipe
bin/mitamae local -o user/fish/default.rb
```

## Platform Support

- **Gentoo**: emerge/portage
- **Arch**: pacman for the official repositories, paru for the AUR

Platform detection happens automatically via `node[:platform]` in mitamae recipes.

### Arch packages

`system.rb` runs under sudo and paru refuses to run as root, so official packages go through the `package` resource (pacman, as root) and AUR packages through the `aur_package` define, which drops to `ENV['SUDO_USER']`. Prefer an official package whenever one exists -- only `1password-cli`, `docker-rootless-extras`, `frgm`, `google-cloud-cli`, `kagiana`, `nkf` and `win32yank-bin` still need the AUR. The wheel group gets passwordless `pacman` because paru shells out to it with no tty to prompt on.

The Arch WSL rootfs was unpacked without xattrs, so anything the image shipped lost its file capabilities. `system/arch/docker.rb` puts back the two that rootless mode needs. Suspect this first when something fails with a permissions error that makes no sense.

### Docker

Docker runs rootless on both distributions. `system/docker/` holds the shared configuration, `system/[platform]/` only the packages, and `user/docker/` owns the systemd user unit -- which needs no platform branch, since both put `dockerd-rootless.sh` at `/usr/bin`.

Things that look redundant but are not:

- The unit is written by the recipe rather than generated by `dockerd-rootless-setuptool.sh`, which bakes the invoking shell's `PATH` into it and then skips the file on every later run. Do not add a `docker.socket`; it would collide with the socket `dockerd-rootless.sh` opens itself.
- `modules-load.d/docker.conf` exists because a user service cannot modprobe `ip_tables`/`overlay`.
- The subordinate UID/GID range is reserved only when the user has none. Changing an existing range orphans everything under `~/.local/share/docker`.
- `fuse-overlayfs` is deliberately absent; the hosts use the native overlay2 driver.

## Configuration Management

- Keep code comments minimal: only concise decision rationale that the code cannot express, such as why an alternative is not used. Put what/how explanations in commit messages.

- System files are templated in `system/[component]/files/`
- User dotfiles managed via `user/dotfiles/` using `mise dotfiles apply`
- Arch installs mise from the official `mise` package; on Gentoo, `user/mise/` installs mise and adds `~/.local/bin` to the provisioning PATH. Dotfiles recipes invoke `mise` through PATH on both platforms
- All configurations are declarative through mitamae recipes
